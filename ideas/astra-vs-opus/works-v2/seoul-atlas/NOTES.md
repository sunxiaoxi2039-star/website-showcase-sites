# 首尔 3D 地图集：独立逆向笔记

## 我对原作的理解（它的核心卖点是什么）

原作 **Seoul 3D Atlas**（synabreu，GPT-6 Astra）把整座首尔做成一块能拿在手里转的沙盘：25 个自治区、真实地形、汉江，二三十万栋建筑，外加一段自动飞过十几个地标的镜头，以及白天、黄昏、夜晚三种光照。它能在 X 上拿到三十万次浏览，靠的是三点：

1. **规模上的真实感**：打开页面看到的是首尔本身，而不是随手捏的一座“风格化城市”。汉江的弯、汝矣岛、南山、北汉山都在它们该在的位置。
2. **微缩模型的质感**：垂直方向夸张过的地形和楼群，加上沙盘底座，让人觉得是在俯看一件桌上的模型，而不是在用 GIS 软件。
3. **会自己讲故事**：点一下“飞越”，镜头就一站一站带你认识这座城。昼夜切换让同一座城有两种性格。

我把复刻目标定为：**真实数据的量感 + 沙盘的质感 + 导览的叙事**，缺了哪一项，这件东西就退回成一个普通的 three.js 城市演示。

## 逆向推断：从有限资料里推出了哪些关键机制，依据是什么

我看不到任何临摹版，也打不开原作 demo（chatgpt.site 被屏蔽），能用的只有推文摘要、社区整理，以及原作 GitHub 仓库公开的 README。我只读了 README 的文字说明，没有看它的源码和脚本。

| 推断 | 依据 | 我的做法 |
|---|---|---|
| 建筑来自 OSM 足迹，数量在 28 万左右 | README：“285,841 buildings from OpenStreetMap”“simplified oriented masses” | OSM 瓦片源被屏蔽，改从 **Overture Maps**（S3 上的 GeoParquet，大部分要素源自 OSM）拉取。按 row group 的 bbox 统计做 HTTP Range 读取，只下载首尔范围内的数据：60.7 万栋原始足迹，筛选后保留 **399,770 栋** |
| 建筑是“带朝向的体块”，并非真实多边形挤出 | README：每栋 6 个 float（x, z, 宽, 深, 角度, 高） | 同样用最小外接旋转矩形，再按面积比例缩小，保证体量不虚胖；每栋压到 14 字节（uint16 量化），整个文件 5.6 MB |
| 高度大量缺失，需要估算 | README：“Heights may be estimates” | 有高度或层数的只占 17%。其余按面积、长宽比和所在用地估算：住宅用地里的细长板楼判为 12–24 层公寓，商业区的大体量抬高，学校、工厂压低 |
| 垂直夸张 | README：“exaggerated 4 times” | 试过 3 倍，江南变成曼哈顿式的针林，最后定为地形 2.2 倍、建筑 2.0 倍 |
| 地形来自 AWS Terrain Tiles | README 原文 | 同一数据源：48 块 z12 Terrarium 瓦片，重采样成 728×626 的网格 |
| 汉江需要专门处理，水面和地形会互相穿插 | README 的版本记录里有大量“汝矣岛水面露出”“下游河道被底座盖住”之类的修补 | 这是我认为最关键的线索。我没有另铺一张平面水面，而是**把水画进地形着色器**：用 4096 px 的水域掩码逐像素判断水面，岸线精度约 10 m；同时把地形网格压到水位以下。支流会跟着真实海拔走，不会被一张平面水面吞掉 |
| 14～21 个地标、自动飞行、区选择 | 推文与 README | 22 个地标，全部配中文卡片和巡游镜头；可悬停、点选 25 个区 |

## 实现思路与关键技术决策（为什么这么选）

**数据管线（离线 Python，产物直接静态托管）**

- Overture 的 building / segment / water / land_use / land_cover / land / division_area 七个图层，加上 AWS 地形，统一投影到以市厅为原点的等距平面上（1 单位 = 1 km）。
- 很多东西直接烘焙成纹理，没有做成几何体。4096×3524 的地面图里有土地覆盖、公园、次级道路、铁路，还有**全部 60 万个建筑足迹的屋顶色块和一圈模糊的接触阴影**。小于 60 ㎡、没有做成体块的小房子也画在地面上，所以老城区的肌理是完整的。
- 另外烘焙了一张**夜间灯光图**：道路按等级发暖橙光，城区按建筑密度加一层泛光，首尔市界以外的区域调暗。夜景的“卫星城市灯火”效果基本来自这一张图，运行时几乎不花成本。
- 主干道只有桥梁段做成几何体：桥面带、侧面灯带、水中桥墩。地面上的路已经在纹理里，再铺一层带状几何体只会和地形打架，产生 z-fighting。

**渲染（three.js r170，无构建，importmap）**

- 建筑按 12×10 个区块分成 InstancedMesh。每个区块内的建筑按“屏幕尺寸重要性”降序排列，每帧用二分查找算出这个距离下多大的楼还能占到 1.3 像素，只画排在前面的那些，也就是 `mesh.count` 截断。这样全景视角实际只画几万栋，拉近看才画全。视锥剔除和阴影剔除都按区块做。
- 建筑着色器在片元里程序化生成窗格：层高、窗宽随建筑类型变化，每扇窗按哈希决定亮不亮。用 `fwidth` 判断窗格已经小于像素时，平滑过渡到平均亮度，避免远处闪烁。首尔屋顶常见的绿色防水漆、韩屋的深灰瓦屋顶、玻璃塔楼的顶冠灯带都写在这段着色器里。
- 连续昼夜：用简化的天文公式按首尔纬度算太阳和月亮方位，天空、雾、半球光、水色都按太阳高度角在关键帧之间插值。亮灯比例跟钟点走，傍晚最多，深夜减少。
- 阴影相机每帧跟着视点缩放（0.6–30 km），并按纹素对齐。这样拉近时阴影清晰，全景时仍然有山影和楼影。
- 后期：Bloom，强度随夜色变化；移轴景深（Tilt-shift），强度随俯仰角自动变化，平视时强、俯视时弱，这是“微缩感”的来源；最后加轻微暗角和饱和度。

**地标**：22 处全部程序化建模。乐天世界塔用超椭圆截面的锥形放样，顶部是开放钢构；N 首尔塔夜里会循环变色；63 大厦是金色梯形；DDP 是挤出后倒圆角的曲面；崇礼门和兴仁之门有重檐门楼，兴仁之门另有瓮城。景福宫按真实宫墙范围布置光化门、兴礼门、勤政殿回廊、庆会楼池、香远亭和各个院落；韩式屋顶的四角都有起翘。

**动态**：14,000 个车流光点（右侧通行，白色是车头灯、红色是尾灯）；盘浦大桥的月光彩虹喷泉由 GPU 粒子实现，只在桥体跨水的那一段喷射；金浦机场有航班按真实跑道方向（约 136°）起降；超高层楼顶有闪烁的航空障碍灯；另有雨、雪粒子，以及季节带来的树色和地面色变化。

## 和「常规做法」相比，我做了哪些不一样的尝试

1. **水面并入地形着色器**。常规做法是一张平面水面加地形，结果就是原作 README 里反复修补的那类问题。我让水“长”在地形上，岸线精度由纹理决定，与网格精度无关。
2. **把屏幕尺寸 LOD 做进实例化**。不用 THREE.LOD，而是靠排序加 `count` 截断，零额外 draw call。
3. **夜景主要靠一张烘焙灯光图**，而不是成千上万个点光源。水面用 mip 偏置采样灯光图，做出模糊的倒影。
4. **移轴景深跟着俯仰角走**：斜看时更像模型，正俯视时像地图。
5. **信息层**：可点击的小地图，上面画着视锥投影；鼠标悬停时显示区名、面积和海拔；区界做成会升起的半透明光幕；地名标签按优先级做碰撞避让。
6. **自适应画质**：帧率低时自动降像素比、提高 LOD 阈值。移动端另有底部抽屉式 UI。

## 踩过的坑与修正过程

- **端口被占**：本地 8765 端口上跑着别的项目，第一次截图连到了别的页面。只看到了它的标题，随即换成独占端口。
- **楼太高**：第一版建筑 ×3、公寓判据过宽，旧城区冒出一片 200 米的“板楼”。改为只在住宅用地里判定公寓、收紧面积阈值，并把夸张系数降到 2。
- **夜景过曝**：第一版夜景全屏泛金，近景地面糊成黄色。加了指数压缩、随相机距离衰减的地面辉光，并调高 Bloom 阈值。
- **夜里楼身发灰白**：我一度以为是月光，逐个关掉光源排查后发现，截图会滞后一帧，干扰了判断。真正的原因是窗格在半像素尺度上混叠。把 LOD 过渡提前，并把平均亮度改成暖色低值后解决。
- **道路越界**：Overture 取数范围比沙盘大，桥和车流悬在沙盘外面的虚空里。在构建时按沙盘范围裁剪折线。
- **天空断层**：地平线辉光用了 `step()`，远景中出现一条硬边，改成对称的指数衰减。
- **魔幻岛放错位置**：按记忆的坐标，城堡落在了室内乐园旁边。改用 Overture 的 theme_park 多边形重新定位到石村湖的岛上。
- **小地图整块变蓝**：水域 PNG 是灰度图，没有 alpha 通道，`source-in` 失效。改为逐像素把亮度转成 alpha。
- **手机端面板默认展开**：ID 选择器的优先级盖过了 `.sheet { display: none }`。

## 自评：和原作相比，哪里可能追平或超越，哪里还差

**可能追平或超越**
- 数据量级相当：约 40 万栋建筑，原作约 28 万；另有 7 万棵树和完整的地面肌理。
- 夜景更有层次：烘焙灯光图、逐窗亮灯、水面倒影、桥梁灯带、喷泉、航空灯。
- 昼夜是连续的，可以拖动或让时间流动，而不只是三档。
- 景福宫做到了院落级别，DDP、乐天世界塔、63 大厦都有辨识度。
- 交互信息层更完整：小地图视锥、区域悬停、标签避让、手机端适配。

**还差**
- 地铁线路、登山步道、酒店、文化遗产这些原作 v1.9 的专题图层没有做：Overture 的地铁数据缺少线路编号，无法可靠着色。
- 建筑高度有 83% 是估算的，个别街区的天际线不够准确。
- 体块仍然是旋转矩形，复杂平面（L 形、弧形）的建筑会失真。
- 数据总量约 18 MB，首次加载比理想的更重。
- 无头 SwiftShader 下只能静态验证，真机 GPU 上的帧率我没有亲测，只做了自适应兜底。

## 如果重来一次会怎么做

- 数据管线一开始就用瓦片化的二进制，按视野流式加载，而不是一次性加载全部 40 万栋。
- 高度估算改用有标注的 7 万栋建筑训练一个小回归模型（面积、长宽比、用地、到地铁站距离 → 高度），取代手写规则。
- 大型建筑用真实足迹挤出，小建筑保留实例化体块，两者混合。
- 夜景加一层屏幕空间的水面反射（SSR 或平面反射，只取汉江范围），让大桥和两岸灯火的倒影更真实。
- 更早搭好“确定性截图”工具：逐帧手动渲染，而不是依赖 requestAnimationFrame，这样能省下大量排查截图滞后的时间。
