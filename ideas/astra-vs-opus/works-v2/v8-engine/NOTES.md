# 交互式 V8 发动机 · 独立逆向心得

## 我对原作的理解（它的核心卖点是什么）

原作的一句话 prompt 是「highly detailed, interactive visualization of a V8 engine」，而公开报道把它描述成「可操作的 3D 课堂」：四个冲程能实时切换，还能看曲轴、凸轮轴、点火顺序、气门正时和气缸压力。我认为它的卖点有三层：

1. **机械真实感**：不是一个转圈的模型，而是活塞、连杆、曲轴、凸轮、气门之间真正“咬合”的运动学关系，看上去“就是会这么动”。
2. **把看不见的东西可视化**：点火顺序、气门重叠、缸压峰值这些平时只在教科书曲线里出现的概念，和 3D 画面同步出现。
3. **动手**：用户不是看视频，而是能切冲程、换视角、拆开看。

所以还原的关键不是“建一个好看的 V8”，而是**让 3D、曲线和文字解释由同一个物理模型驱动，任何一处的变化都能在其它地方同时看到**。

## 逆向推断：从有限资料里推出了哪些关键机制，依据是什么

没有 demo，只有一句描述和作者的风格参考，所以大部分机制是从“V8 真实工作原理 + 描述中点名的五个功能”反推的：

- **曲轴类型 → 横置平面（cross-plane）**：报道点名“点火顺序”，而最具教学价值、最常见的 V8 就是 90° 夹角 + 曲柄销 0°/90°/270°/180° 的横置平面曲轴，点火顺序 1-8-4-3-6-5-7-2（GM 编号）。我没有手写每缸相位，而是只给定“点火顺序 + 缸列夹角”，再**反解出每个曲柄销的角度**；解出来左右两缸共用同一销、四销恰好互成 90°，说明模型自洽。顺时针旋转 + 奇数列在前视右侧，与真实 GM 布局一致。
- **“实时切换四冲程”→ 以单缸循环角 ψ 为中心**：切换冲程的本质是“把聚焦缸拨到该冲程”。我把每缸状态定义为 ψ = θ − 点火相位（0° = 压缩上止点），所有显示（缸内气体颜色、气门、曲线游标、HUD 文案）都从 ψ 推导，所以切换就是让曲轴向前转到目标 ψ，而不是切换动画片段。
- **“气门正时”→ 真实的正时参数和凸轮型线**：采用典型的 IVO 12° BTDC / IVC 48° ABDC / EVO 52° BBDC / EVC 10° ATDC，重叠 22°；凸轮轴 2:1 减速。凸轮外形不是随便画的，而是用同一条升程曲线按极坐标（基圆 + 升程，凸轮 1° = 曲轴 2°）逐点生成，所以凸尖压下挺柱的时刻和升程曲线严格一致。
- **“气缸压力”→ 不是画一条假曲线，而是算出来**：单区热力学模型 + Wiebe 燃烧放热函数，从进气门关闭积分到排气门打开，再用指数衰减近似自由排气。得出 WOT/3000 rpm 下峰值约 68 bar @ 14° ATDC、IMEP 13.5 bar、扭矩约 470 N·m——都在真实 5 L 自然吸气 V8 的量级内。这让“调点火提前角”变成真实的物理实验。
- **作者审美**：同一作者的另一件作品是“2D 原理图自然过渡成 3D”。我推断他偏爱工程制图式的清晰感，于是把“原理图 ⇄ 3D”做成本作的一个视图模式。

## 实现思路与关键技术决策（为什么这么选）

- **Three.js（本地 vendor，importmap，无构建）**：WebGL 程序化建模最成熟、可静态托管。只拷贝了用到的 13 个文件（2.3 MB）。
- **全部几何程序化生成**：没有 glTF。缸体用“截面 + 拉伸”构造（缸列截面带缸孔和缸盖螺栓孔，曲轴箱是前视轮廓沿轴向拉伸），这样每个壳体都是封闭实体——这是剖切面能正确“填色”的前提。曲轴臂、连杆是 2D 轮廓挤出，活塞/气门/火花塞是车削体，凸轮是由升程函数生成的型线挤出，正时链与多楔带沿“圆的凸包切线路径”排布。
- **剖切 = 裁剪平面 + 背面填色**：每个缸列的壳体用“过缸轴线的平面”裁掉谷侧一半，背面用斜线红色着色器渲染，形成经典的机械剖视图截面。缸盖在剖切模式下换成“燃烧室板 + 凸轮轴承座”骨架，让排气门也能被看见。
- **一个物理模型驱动一切**：`physics.js` 是纯函数（可在 node 中测试），`computeCycle()` 输出 0.5° 分辨率的 p、V、已燃质量分数、放热率、温度。3D 中缸内气体的颜色/亮度、火焰前锋、排气管发红、气流粒子速度、声音、所有图表都从它采样。
- **原理图转场**：两组裁剪平面互补——实体材质保留扫描线右侧、蓝图材质保留左侧，扫描线横扫的同时摄像机做 dolly-zoom（按“视高不变”插值 FOV 与距离），透视自然压扁成近似正交的前视图。蓝图材质是“填充 + 菲涅尔轮廓线 + EdgesGeometry 棱线”，内部零件不透明（自动消隐），壳体只画轮廓（能透过去看），最后叠上 SVG 尺寸标注（90° 夹角、缸径、行程、中心线）。
- **可见性用 layers 而不是 visible**：layers 不向子节点级联，于是“实体隐藏、它的蓝图副本仍显示”可以共存，转场时两边同时渲染。
- **UI 用 Canvas 2D 自绘图表**：p–θ（线性/对数）+ 升程叠图、p–V 环线、气门正时圆图、8 缸 × 720° 相位图、带冲程色带的拖动条，全部每帧重绘，与 3D 同步。

## 和「常规做法」相比，我做了哪些不一样的尝试

- **常规做法**：一个旋转的 V8 模型 + 四个按钮播放对应的动画 + 一张静态的气门正时示意图。
- **我的尝试**：
  1. **参数可调、结果可算**：点火提前角、节气门、转速、进气 VVT 都会实时重算缸压循环；面板会给出压力峰值位置、爆震风险提示，并**自动扫描求出当前工况的 MBT（最佳扭矩点火角）**。拖动 VVT 能看到进气凸轮整体相对转动、气门重叠在圆图上变大。
  2. **凸轮型线由升程曲线生成**，而不是一个“蛋形”。
  3. **缸内气体是状态体**：进气蓝 → 压缩变紫变密 → 火焰前锋从火花塞向外扩张 → 做功橙红 → 排气褐色，高度随活塞实时变化；排气门打开时对应排气歧管短暂发红。
  4. **2D 原理图 ⇄ 3D 的扫描转场**，在线稿里活塞和气体仍在运动。
  5. **声音按物理事件合成**：在每缸 EVO（排气门打开）时刻触发脉冲，奇数列/偶数列分别声像左右——横置平面曲轴同一列点火间隔不均（270°/180°/90°/180°），自然出现 V8 的“突突”声。慢放时是一声声独立的“砰”，实时模式下连成轰鸣。
  6. 点火顺序同时用三种方式表达：顺序条（当前做功缸点亮）、8 缸 × 720° 相位图（能一眼看出做功段每 90° 错开的“阶梯”）、3D 气缸编号标签上的点火闪烁。

## 踩过的坑与修正过程

- **第一版整屏“白茫茫”**：缸内气体用加法混合 + 较低 bloom 阈值，金属高光和气体叠加后全部溢出成白色。改为 Alpha 混合的气体体积（保色相）、bloom 阈值提到 1.9、降低 RoomEnvironment 反射强度并补一盏半球光，只让燃烧和火花真正发光。
- **剖切后右列看不到活塞**：裁剪平面过缸轴线，摄像机若在右前方，右列正好“侧对”镜头。把默认机位移到更靠正前上方，让两列谷侧剖面都朝向观众。
- **剖切模式下进气歧管消失导致气流粒子“悬空”**：改为剖切时进气歧管以淡幽灵材质显示，给粒子一个“管道”的语境。
- **粒子几乎不可见**：点大小按固定系数算，只有 1 像素；改为按画布高度与 FOV 推导的屏幕空间尺度。
- **高亮部件时共享材质串色**：同一材质被多个部件共用，选中曲轴时螺栓也发光。改为按“材质 × 部件”克隆，高亮与虚化都按部件精确生效。
- **正时罩盖最初是随手画的扇形**，外观模式下很假。改为对所有链轮外包圆求凸包，再沿边缘均布螺栓。
- **无头 SwiftShader 下约 1 fps**：截图会拍到旧合成帧；测试脚本改为等加载完成、关闭 CSS 过渡、加长超时，并暴露 `__v8.finish()` 直接推进转场以便验证。
- **手机端**：面板改为舞台下方纵向排列、传动条紧跟 3D 视图；用 `camera.zoom` 按宽高比缩放，390 px 宽无横向溢出。

## 自评：和原作相比，哪里可能追平或超越，哪里还差

- **可能追平/超越**：
  - 物理真实度：点火顺序、曲柄销相位、气门正时、缸压都是算出来且互相一致的，并且可以动手调参看因果（提前角 → 峰值位置 → 爆震/MBT）。
  - 原理图 ⇄ 3D 转场和线稿中的实时运动，是原帖没有提到的维度。
  - 数据面板的密度（p–θ、对数、p–V、正时圆图、720° 相位图）应该比多数同类作品更“能教东西”。
- **还差**：
  - 视觉精度：程序化几何没有铸造纹理、倒角细节和 AO，缸体表面偏“干净”，离照片级渲染还有距离；原作若使用了更精细的建模或贴图，外观模式会明显强于我。
  - 没有真正的爆炸图（部件沿轴向拆开）动画，只有“选中高亮 + 其余虚化”。
  - 气流只是沿路径的粒子，不是流体；缸内涡流/滚流没有表现。
  - 无法看到原作视频，交互布局是按描述推断的，镜头语言可能和原作不同。

## 如果重来一次会怎么做

- 先搭好“ψ 驱动一切 + 物理模型”这一层再建几何——这次也是这么做的，收益很大；但会更早定下光照与后期参数，避免后面反复调 bloom。
- 用 SDF/法线贴图给缸体加铸造质感和倒角，在 GPU 上做屏幕空间 AO。
- 加入“爆炸图”模式：各部件按装配层级沿自身轴线分离，并能逐级还原。
- 用 AudioWorklet 做连续的排气声合成（含进气谐振），而不是离散脉冲。
- 把原理图模式扩展成可切换的剖面位置（任选一缸做横剖面）。
