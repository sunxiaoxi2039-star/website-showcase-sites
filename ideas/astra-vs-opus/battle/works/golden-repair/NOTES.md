# Golden Repair · 创作笔记

## 对题目的理解与取舍

- **"digital art object"**：我把它理解成一件可以静静看的作品，不是一个网站。所以页面上只有四样东西：碗、标题、题签、金字，没有导航、页脚或额外的说明区。
- **碗**：用正俯视角度。俯视时看不到碗的外壁，只能看到口沿和内壁，所以同心结构是这样安排的：口沿（外缘带一圈"口红"铁锈色）→ 内壁（米白色的灰釉）→ 碗底积釉（偏青绿、有光泽的一汪釉）。"concentric glaze gradients" 用一个 14 段色标的径向渐变做，上面再叠几道略微偏心的拉坯纹（每道圆的圆心有 1–2 个单位的偏移，让它看起来像手工拉出来的）。光从左上方来：左上内壁被口沿挡住，落在阴影里；右下内壁受光。
- **裂纹**：11 条手写的折线路径。5 条主干从口沿断开，6 条分支停在釉面中间；口沿还有一处崩口，露出没上釉的陶胎。说明文字里"Eleven lines"这个数字和实际路径数一致。
- **金色字**：选了「金」（kin，意思是金），用 8 个填充笔画手工画成 SVG，没有依赖系统的 CJK 字体，因为评审机上不一定有明朝体。"reflective copy" 有两种读法，我两种都做了：一是字下方有一个倒影（像漆面上的反光），二是旁边一段沉思性的短文。
- **两段式说明**：I — The break → II — The mend。中间有一条金色进度线，跟着描金的进度一起填满。按钮的三个状态：Repair in gold → Tracing the seams…（不可点击）→ Return to the break（金线以 2.6 倍速退回）。
- **"tribute, not a craft tutorial"**：标题下方有一个胶囊形的 "A TRIBUTE" 标签，接着一句明确的话："offered as a meditation, not a craft tutorial. No techniques are taught here."；`<title>` 和 meta description 里也写了。全文不提漆、粉、工序等任何工艺步骤。

## 关键技术决策

- 纯 SVG 加少量原生 JS，没有用任何库。碗和金线分成**两层 SVG**：静态层带 feTurbulence 釉斑、颗粒和多重模糊滤镜，只绘制一次；动态层只放裂纹和金线。这样描金时每一帧只需要重绘轻量的那一层。
- 描金：每条裂纹克隆出三层（模糊光晕，混合模式 screen / 金色渐变主线 / 偏移 0.5px 的高光细线），三层都用 `stroke-dasharray = 实际长度`，由 `stroke-dashoffset` 从长度推进到 0。
- 时间轴自动生成：主干按 delay 从口沿开始描。分支的起点用 `getPointAtLength` 采样父路径，找到最近点，**等金线走到这个岔口时分支才亮起来**。每条正在描的路径的笔尖有一个跟随的光点。崩口在它那条裂纹描完以后被金色填满。
- 描完以后，金线和「金」字的渐变会缓慢游移，也会跟随指针移动，像光在金面上流动。页面隐藏或开启 reduced-motion 时停止。
- `prefers-reduced-motion`：不播放行进动画，也没有光点和游移，金线直接出现，说明文字直接切换。
- 字体：从 npm 拉取 @fontsource 的 Cormorant Garamond（300 正体、400 斜体）和 EB Garamond（400 正体和斜体）的 latin 子集，以 base64 内联（OFL 许可），约 128KB。完全离线，没有任何网络请求。
- 响应式：宽屏时四个角加中央的碗用绝对定位布局，碗的尺寸是 `min(84svh, 60vw, 800px, (100vw-560px)*1.17)`，避免压到两侧文字。窄屏或竖屏（≤900px 或宽高比 <1）改成单列流式排版。

## 自测时发现并修掉的问题

1. 碗内侧的"口沿投影"一开始用 mask 做，边缘是硬的，像一块灰色的月牙。改成模糊 mask 以后，在 Chromium 里整层不显示了。最后改用偏心粗描边圆加高斯模糊，再裁到内壁，效果自然，也更稳。
2. 釉面斑点的 colorMatrix 阈值写错了，整只碗像撒满黑胡椒。改成只取噪声 R 通道的高端值，得到稀疏的铁斑。
3. 碗底积釉的高光太像一个凸起的玻璃球。改成弱化光泽，加上左上暗、右下亮的弧形反光，读起来像凹下去的一汪釉。
4. 本机 Chromium 不认 Bitstream Charter，标题退回成了 Liberation Serif。于是内联了 Garamond 系字体。
5. 在 1024×768 下碗压到了左上角的文字，按钮文字也折行了。加了宽度约束，按钮设为 nowrap。
6. 移动端的按钮刚好卡在首屏底边，收紧了间距。
7. 在无头软件渲染下帧很慢，把单帧 dt 的上限从 64ms 调到 120ms，让动画时长更接近真实时间。

在 1400×875、390×844、1024×768 三个尺寸下都检查过，另外跑了 reduced-motion 和键盘 Enter 触发"修复→复原"的完整来回。均无横向溢出，控制台零报错，零网络请求。

## 自评

- **最满意**：分支"等金线流到岔口才被点亮"。描金的过程读起来像一种液体沿着裂缝自己找路，不是 11 条线同时开始播放。
- **最不满意**：碗的釉面还是偏"干净的数字渲染"，缺少真实茶碗那种釉层流淌、缩釉和厚薄变化的偶然性。拉坯纹也略显规整。
