# Eclipse Chamber — 笔记

## 对题目的理解与取舍
- 关键词是“art chamber / cinematic / explicitly artistic”：这是一件装置而不是天文仪器，所以几何只保留“可信的骨架”（真实的圆面遮挡面积、食分、接触点顺序），比例与光效都刻意夸张，并在页面角落明写 “Artistic rendering — not to scale · Moon ⌀ +8% · corona ×3.5”。
- 月亮半径设为太阳的 1.08 倍（真实只有约 1.0–1.07），让全食在滑杆上有一段可以“停留”的区间。
- 滑杆到月亮位移用 `|u|^1.8` 的非线性映射：越接近对齐，月亮走得越慢，全食附近像时间被拉长——这是整件作品的“电影感节奏”来源。
- 页面默认落在全食（稍偏心，让一侧色球层露出一点），打开即是高潮画面；TOTALITY 字样在非全食时只有 16–26% 亮度，全食时点亮并把字距从 0.62em 撑开到 0.92em。
- 布局极简：大面积近黑场、居中太阳、一行超宽字距 TOTALITY、四角 9px 等宽小字元数据、底部一条细线滑杆。

## 关键技术决策
- 纯 DOM + CSS 分层（无 canvas 主体、无 WebGL）：日冕 = 三层由种子随机生成的 `conic-gradient` 射线（宽流/细射线/极羽），各自用径向 mask 限定在日面外、`filter: blur()` 柔化并以不同速度反向缓慢旋转；外加一层 K 冕径向光。星空用 canvas 只画一次（避开文字区域）。
- 状态机按真实几何：圆-圆交叠面积算遮挡率、食分 (R+r−d)/2R、角距（按太阳 32′ 换算）、以及虚构的 4m27s 全食时长推出的 T± 时钟；阶段依次为 Before C1 → C1 → Partial ingress → Diamond ring → Baily’s beads → C2 → Totality / maximum → C3 → … → After C4。
- 钻石环位置取月心偏移方向对侧的日缘；贝利珠用 11 个“月谷”采样点、按日缘点到月缘的间隙做高斯强度。
- 交互：原生 range（键盘/读屏可用，aria-valuetext + aria-live 只在状态变化时播报）、可直接拖动月亮、播放按钮做一次缓慢凌日、全局快捷键 T 回到全食 / ←→ 微调 / 空格播放。
- 字体：Jost 200/300 与 IBM Plex Mono 400（OFL）从 npm 拉取 latin 子集，base64 内联，约 45KB；零网络请求，file:// 直接运行。

## 自测中发现并修掉的问题
1. 星点过密过亮、带光晕，像灰尘并压到文字上 → 降密度与亮度，只给少数亮星加晕，并在绘制时避开所有文字块。
2. 日珥是饱和的粉色圆斑，像贴纸 → 缩小、降饱和、加模糊，色球层环也减弱。
3. 钻石环太弱，不够“标志性” → 放大光斑、加亮核心、延长十字光芒、减慢强度衰减、用 screen 混合。
4. 月面偏灰（被颗粒层提亮）→ 压暗月面渐变。
5. 渲染走 rAF 时，慢机上读数会滞后一帧 → 改为输入时同步渲染。
6. 播放时 dt 上限过小，低帧率下几乎不动 → 放宽上限。
- 两个视口（1400×875、390×844）均无横向溢出，控制台零报错、零网络请求。

## 迭代轮数
共 5 轮（首版 → 星空/日珥/月面 → 钻石环 + 移动端检查 → 交互功能测试 + 同步渲染 → 文字避让星点 + 终检）。

## 自评
- 最满意：非线性滑杆带来的节奏——越接近对齐越慢，钻石环一闪之后日冕与 TOTALITY 同时亮起、字距慢慢撑开，那一下很有仪式感。
- 最不满意：日冕仍是“旋转的射线纹理”，缺少真实日冕那种磁力线弯曲的流线结构；日珥也偏装饰化。
