# Solar Garden · 创作笔记

## 对题目的理解与取舍
- 我把题目读成“一张数学植物学图版”：左栏是编辑式文字（标题、导语、控件、随角度变化的解读、数据），右栏是一张可交互的 Vogel 向日葵图版（Fig. 1）；下方再接“Field notes”三栏短文、公式带和“Herbarium”六张标本小图。移动端用 grid-area 重排为：标题 → 图版 → 控件 → 解读 → 正文，这样拖动滑杆时花盘就在正上方。
- 配色：森林黑 `#070c08` 底、淡黄绿 `#e2f1a4` 文字；种子由中心的近白黄绿渐变到边缘的橄榄色，形成“太阳”式的发光花心。金色 `#e6b949` 只用于标记黄金角。
- “解释会变化”是我花最多心思的部分：解读不是几段预写文案切换，而是按数论实时算出来的——
  - 对 α/360 求连分数，并显示出来（黄金角是 [0; 2, 1, 1, 1 …]，135° 显示为 [0; 2, 1, 2] rational）；
  - 用 N·|qx − p| < 1 判定“直辐射线”（种子每 q 步回到同一方向），得到 “Eight straight rays / A comb of forty-five rays” 等标题；
  - 用“第 n 与 n+q 颗种子在外缘的间距” d² = q²/4N + 4π²δ²N 找出边缘肉眼可见的两族螺旋（黄金角下正好是 55 与 89，并给出顺/逆时针方向）；
  - 以“最近邻距离的第 10 百分位”衡量排布均匀度，并归一到黄金角 = 100%。
  共六种状态：Golden / Rays / Fine rays / Near golden / Another order（例如 139.525° 同样均匀但螺旋数 49·80 不是斐波那契数）/ Spiral arms。
- 花瓣（舌状花）是同一序列的第 988–1042 项，所以角度变成有理数时花瓣也会聚成 8 束、5 束，形态和种子一起变化。
- 界面语言用英文（原题是英文）。

## 关键技术决策
- 纯内联 SVG + 原生 JS，零依赖。987 个 `<ellipse>`，每次只更新一个 `transform`（translate + rotate，使长轴朝外），拖动流畅。
- 字体：从 npm 拉 @fontsource 的 Fraunces（300/300 italic/400）、IBM Plex Mono（400/500）和 EB Garamond 的希腊文子集（只用于 α、θ、φ，通过 unicode-range 生效），全部以 base64 woff2 内联，文件约 198 KB，file:// 下直接可用，无任何网络请求。
- 滑杆上方有一条“均匀度地形图”：分片（每片 12 ms）计算 601 个采样角的均匀度，逐步画出，不阻塞首屏；在 3/8、2/5、5/13 等有理角处可见深谷，黄金角是峰值（数值上验证过它是 130–145° 网格上的最大值）。滑杆下方的 4/11、3/8、8/21、5/13、2/5 刻度可以点击跳转。
- 滑杆用 `step="any"`，并自定义键盘：方向键 ±0.01°，Shift ±0.1°，PageUp/Down ±1°，G 回到黄金角。“Golden angle”按钮做 easeInOut 补间，让花盘连续地变回去；“Sweep”自动在 130–145° 之间往返扫描；“Trace arms”按主螺旋族明暗交替着色，悬停/轻触任一种子会画出穿过它的两条螺旋，并标出 ±55、±89 邻居。
- 外圈是量角器刻度，α 用弧线表示在圈上，金色菱形标出 137.508°。

## 自测中发现并修掉的问题
1. `text-transform: uppercase` 把 α 变成了大写 “A”（标签、图注、公式说明、页脚都有）→ 给希腊字母单独包 `.gk`，取消大写并单独放大。
2. 内联字体缺 α/θ/φ/√/≈、细空格等字形 → 加 EB Garamond 希腊子集；√ 用内联 SVG 根号画；≈ 和 thin space 改写成字体里有的字符。
3. 1400×875 下左栏超出首屏，统计行被截断 → 压缩标题、导语、图表高度和间距，并缩短黄金角解读文案。
4. 均匀度一开始用最近邻距离的平均值，曲线噪声大、黄金角不突出 → 改用第 10 百分位（对拥挤更敏感），并离线验证了峰值位置。
5. 解读文字与“Rim spirals”统计不一致（比如文案说“34 and 191”，统计只显示 34），第二族螺旋会选到 q=228 这种没意义的值 → 第二族限制在 q ≤ 144，且两族距离相近时才成对显示，文案和统计共用同一个判定结果。
6. 139.5° 附近均匀度 100% 却被描述成“有缝隙的旋臂” → 新增 “Another order” 状态。
7. 移动端：130°/145° 端点标签和 4/11、2/5 重叠；三个按钮折成两行；统计小字被截断；图注贴着导语；外圈刻度字太小；轻触无法触发种子探针 → 分别修正（端点标签另起一行、按钮三等分网格、改短文案、加间距、移动端放大 SVG 字号、增加 pointerdown）。
8. 语法错误一次（拼接引号不匹配）→ 用 `node --check` 抽出脚本校验后修复。
最终在 1400×875 和 390×844 下都没有横向溢出（scrollWidth = clientWidth），控制台零报错，零网络请求。

## 迭代轮数
约 6 轮（初版 → 希腊字母/字形与首屏压缩 → 均匀度指标与分类逻辑重写 → 探针与统计一致性 → 移动端修整 → 最终文案与回归测试）。

## 自评
- 最满意：解读是算出来的，而不是写死的——连分数、直辐射线数、边缘螺旋族数和均匀度都在实时计算，所以任意角度（包括 139.525° 这种“另一种秩序”）都能得到正确、具体的说明；花瓣随角度聚成 8 束或 5 束，效果也很直观。
- 最不满意：均匀度地形图本身是分形式的锯齿（数学上确实如此），在小尺寸下看起来有点像噪声；种子是纯色椭圆，没有做更细的种皮纹理或光照，近看质感还可以再提升。
