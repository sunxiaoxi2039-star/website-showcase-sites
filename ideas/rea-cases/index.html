02REA 背后原理

REA 接入的负责分析程序运行逻辑的工具，很多早就存在了。REA 把它们接到 Agent 身上：Agent 自己调用、继续追问，最后把结果整理出来。它确实用到了不少现有开源项目——

Ghidra分析编译后的程序

NSA 开源的逆向工程框架，用来拆解原生二进制。

github.com/nationalsecurityagency/ghidra

Hopper / IDA商业分析工具，也能接

具体用哪一套，要看你分析的目标。REA 本身包含本地工具，既能从终端调用，也能作为 MCP 服务接给 Agent。

工作循环agent-in-the-loop

有了 MCP，Agent 可以发出具体操作——搜索函数、查看代码、追踪调用关系；REA 把工具结果返回来，Agent 再决定下一步查什么。REA 还配了操作说明，告诉 Agent 遇到不同目标该怎么调查；返回的分析结果会记录依据和限制：哪些查到了、哪些还不能确定，尽量交代清楚。这对后面判断它有没有理解对、重写得对不对，很有帮助。

你提出想研究的功能 → Agent 用 REA 去查 → 整理出规则 → 写一个适合你项目的版本 → 测试和调整。做出来的新工具，是这几步一起完成的。

03怎么安装

最懒的方式：直接把原文章丢进 Agent，让它帮你装好并教你怎么用。或者自己先准备好 Node.js 和 npm 环境，然后执行——

$ npx rea-agents@latest setup
  1. 按提示选中你实际使用的 Agent，比如 Codex、Claude Code 或 Cursor。
  2. 它会列出准备修改的配置，你看过以后再确认。
  3. 安装完成，重启对应的 Agent 工具，让新接入的 MCP 和配套操作说明生效。
  4. 想深入研究原生程序的函数逻辑，需另外配好 Ghidra、Hopper 或 IDA；研究部分 JavaScript 桌面应用时，可以先走静态分析路线，不必把所有引擎装齐。
  5. 第一次建议拿自己写的小程序、或者自己有权研究的项目试试。
